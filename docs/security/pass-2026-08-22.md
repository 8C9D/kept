## What shipping adds, and its posture

- **The web bundle** (rebuilt this pass with the final privacy page):
  carries `https://api.keptapp.net` and Apple's JS URL; **zero** instances
  of the dev-token affordance or `localhost:3000` (checked with positive
  controls, wave-6 style); **no sourcemaps**. The session token stays in
  localStorage per the recorded trade (DECISIONS 2026-08-21), and the CSP
  below is the mitigation that trade leaned on.
- **`_headers` is new**: Pages now serves a CSP with a strict `script-src`
  ('self' plus `appleid.cdn-apple.com`, nothing else - no inline script can
  run, which is what makes a script-readable token defensible),
  connect/img/frame scoped to the API and the R2 endpoint, `object-src
  'none'`, `frame-ancestors 'none'`, plus nosniff, a strict referrer
  policy, and a Permissions-Policy denying camera/microphone/geolocation.
  `style-src` carries `'unsafe-inline'` deliberately: the privacy page is a
  standalone `<style>` block and inline CSS is not a script-injection
  surface; recorded rather than smoothed over.
- **The privacy contact** is the owner's own email, on his ruling that
  identity linkage must not block shipping; swapping it later is one page
  edit and one Pages re-upload, nothing else references it.
- **The iOS artifact is unchanged**: build 1.0 (1), uploaded 2026-08-18,
  from the reviewed codebase - no ATS exceptions, no settings screen,
  privacy manifest shipped, keychain posture per the August review.
